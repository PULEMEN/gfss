# Сравнение моделей облачных сервисов

Модель показывает, что предоставляет облачный провайдер и чем управляет пользователь.

| Критерий | IaaS | PaaS | SaaS |
| --- | --- | --- | --- |
| Что получает пользователь | Виртуальные серверы, диски и сеть | Платформу для размещения собственного приложения | Готовое приложение |
| Физические серверы, хранилище, виртуализация | Провайдер | Провайдер | Провайдер |
| Операционная система | Пользователь | Провайдер | Провайдер |
| Среда выполнения и middleware | Пользователь | Провайдер | Провайдер |
| Приложение | Пользователь | Пользователь | Провайдер |
| Данные и права доступа | Пользователь | Пользователь | Пользователь управляет содержимым и доступом, провайдер обеспечивает хранение в рамках сервиса |
| Контроль серверной среды | Высокий | Ограничен возможностями платформы | Настройки готового продукта |
| Собственный программный код | Можно запускать | Можно размещать | Обычно не требуется |
| Когда подходит | Нужны свои ОС, библиотеки и настройки | Нужно разместить свой код без обслуживания ОС | Достаточно готового продукта |

Это учебная схема. Конкретные обязанности зависят от сервиса и его настроек. Например, в IaaS провайдер обслуживает физическую сеть, но правила доступа к виртуальным машинам настраивает пользователь.

## Простой пример выбора

Если учебному центру нужны почта, календарь и документы, подойдёт SaaS. Для своего веб-приложения без обслуживания серверной ОС можно использовать PaaS. Если нужны системные настройки и установка своего ПО на виртуальную машину, подходит IaaS.
