## Порядок выполнения

1. Для каждой части создан отдельный Issue с описанием результата и исполнителем.
2. От main созданы три отдельные ветви.
3. В ветвях добавлены материалы и сделаны коммиты с понятными сообщениями.
4. Для каждой ветви открыт Pull Request в main. В описании указан Closes #1, Closes #2 или Closes #3.
5. Проверены содержание файлов, пути и изменения в Pull Requests.
6. Изменения объединены в main, связанные Issues закрыты.
7. В README указаны роли, задачи и ссылки на материалы.

## Проверка и ограничение

Взаимная проверка другим участником не выполнена, потому что напарника нет. Комментария reviewer и исправления после такого комментария нет. Проверка файлов перед объединением не является взаимным review и не засчитывается за него.

Это отчёт об индивидуально выполненной части, а не подтверждение выполнения всех командных требований. Для полного соответствия заданию нужны второй участник, его изменение минимум в одном файле и участие в Pull Request и review. Как минимум в одном PR требуется исправление после содержательного замечания другого участника. Если преподаватель разрешает индивидуальный формат, его нужно согласовать отдельно.

## Ответы на контрольные вопросы

1. Issues нужны для записи задач, обсуждения результата и назначения исполнителя.
2. Отдельная ветвь позволяет работать над своей задачей, пока основная версия остаётся в main.
3. Pull Request - запрос на объединение изменений. В нём можно посмотреть разницу файлов, обсудить изменения и провести проверку.
4. Comment оставляет замечание без одобрения или требования доработки. Approve выражает одобрение. Request changes запрашивает исправления.
5. Issue описывает задачу, ветвь отделяет работу над ней, commit фиксирует изменение, PR предлагает объединение, а merge переносит изменения в основную ветвь. Связанный Issue может закрыться автоматически после merge PR в основную ветвь при использовании Closes #номер.
