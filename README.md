# Каталог облачных сервисов

Учебный проект по дисциплине **«Основы облачных технологий»**.
Группа: **ДОТ ИСР-262**. Вариант № 1.

## О проекте

Каталог помогает сравнить IaaS, PaaS и SaaS и понять, какая модель подходит для разных задач. Он содержит таблицу моделей и примеры облачных сервисов с официальными источниками.

Учебный прототип представляет собой документацию в Markdown. Его можно открыть на GitHub в браузере или просмотреть локально после клонирования репозитория.

## Категории сервисов

| Модель | Что предоставляется | Пример | Когда подходит |
| --- | --- | --- | --- |
| IaaS | Виртуальные серверы, диски и сеть | Amazon EC2 | Нужен контроль ОС и установленного ПО |
| PaaS | Платформа для собственного приложения | Google App Engine | Нужно разместить код без обслуживания ОС |
| SaaS | Готовое приложение | Google Workspace | Достаточно готовых инструментов |

Подробности находятся в [таблице моделей](lab3/service-models.md) и [примерах сервисов](lab3/service-examples.md).

## Архитектура

В прототипе используются три основных компонента:

1. **Клиент - браузер.** Пользователь открывает README, читает каталог и переходит по ссылкам.
2. **Веб-интерфейс и обработка Markdown на GitHub.** GitHub получает запрос, берёт содержимое файла из репозитория и показывает заголовки, таблицы, ссылки и код в читаемом виде.
3. **Хранилище - Git-репозиторий.** В нём находятся Markdown-файлы каталога и история их изменений.

Взаимодействие: пользователь открывает страницу в браузере, GitHub читает нужный файл из репозитория и возвращает оформленную страницу. После изменения Markdown-файла и коммита GitHub показывает новую версию документа.

Для этого прототипа отдельное серверное приложение и база данных не требуются. Хранилищем данных каталога служат файлы репозитория.

## Структура данных

Данные хранятся в Markdown, без отдельного JSON-файла:

- `lab3/service-models.md` - сравнительная таблица: критерий и значения для IaaS, PaaS, SaaS.
- `lab3/service-examples.md` - карточки сервисов, оформленные отдельными разделами.

Каждая карточка сервиса содержит категорию модели, название, описание, пример применения и ссылку на официальный источник. Для добавления сервиса нужно создать новый раздел по этой же структуре.

## Запуск учебного прототипа

### Просмотр на GitHub

Предварительное условие: браузер и доступ в Интернет. Репозиторий публичный.

1. Откройте [репозиторий PULEMEN/gfss](https://github.com/PULEMEN/gfss).
2. Прочитайте README на главной странице репозитория.
3. Откройте [сравнение моделей](lab3/service-models.md).
4. Перейдите к [примерам сервисов](lab3/service-examples.md).

Ожидаемый результат: отображаются таблица IaaS/PaaS/SaaS и описания трёх сервисов. Установка зависимостей для этого способа не нужна.

### Локальный просмотр

Предварительные условия: установлен Git, есть доступ к GitHub и редактор с предпросмотром Markdown, например VS Code.

1. Выполните команды в терминале:

```bash
git clone https://github.com/PULEMEN/gfss.git
cd gfss
```

2. Откройте папку `gfss` в редакторе.
3. Откройте `README.md` и включите предпросмотр Markdown.
4. Аналогично откройте `lab3/service-models.md` и `lab3/service-examples.md`.

Ожидаемый результат: текст отображается с заголовками и таблицами. Файлы можно читать локально без Интернета; внешние источники открываются при наличии подключения.

## Используемые технологии

- **Git** - хранение истории версий и работа с ветвями.
- **GitHub** - размещение репозитория, просмотр Markdown, Issues и Pull Requests.
- **Markdown** - оформление каталога и отчётов.
- **Браузер** - просмотр опубликованной документации.
- **Редактор Markdown** - локальное чтение и изменение файлов.

HTML, CSS и JavaScript относятся к сайту Tech Academy. Для просмотра самого каталога Python, Docker и установка пакетов не нужны.

В документации размещаются только открытые учебные сведения. Реальные пароли, токены и ключи доступа нельзя добавлять в репозиторий: они могут стать доступны другим людям и остаться в истории Git даже после удаления из текущей версии файла.
